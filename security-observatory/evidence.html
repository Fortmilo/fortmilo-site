SBS & Evidence

Evidence usability before framework mapping.

The Observatory separates whether scanner families returned usable evidence from how retained evidence supports a Security Benchmark for Salesforce control identifier.

The Observatory references Security Benchmark for Salesforce control identifiers to organise supporting evidence. It does not determine SBS compliance and produces no SBS pass/fail result.

SBS defines formal, auditable security requirements. Observatory output is bounded supporting evidence only: no certification, formal compliance assessment, security guarantee or compliance score is produced.

Three different evidence questions

State vocabularies are not interchangeable

This page explains scanner-family status and SBS coverage. Finding-level evidence states are documented separately on the Findings page.

Did this scanner family return usable output?

Scanner-family status

  • Evidence returnedThe family returned usable non-empty evidence for the scan context.
  • Zero observedThe family completed and explicitly observed zero matching records. This is different from missing output.
  • Scanner issueThe family encountered an error, unavailable source or other condition that prevented reliable evidence.
  • Not assessedThe family was not assessed in the stated scan context and must not be interpreted as clean.

How does the Observatory support this SBS control?

SBS coverage state

  • AutomatedThe Observatory can collect the approved supporting evidence directly.
  • Partial EvidenceUseful evidence exists, but it does not fully verify the SBS requirement.
  • Manual RequiredThe requirement needs human verification beyond Observatory evidence.
  • Not CoveredThe current implementation does not assess the requirement.
  • Extended CheckUseful Observatory evidence exists outside direct SBS control coverage.

Mapping model

Local, version-bound identifiers

Where implementation is validated, scanner output is associated with local SBS metadata and stable control identifiers. The mapping supports traceability; it does not copy a compliance decision into the application.

When an SBS version is shown, the application uses the version stored inside the loaded SBS XML metadata. It does not infer the version from a repository release tag.

No SBS control prose is reproduced on this site.

Supporting evidence operations

Review, compare and export safely

Level-aware comparison

Completed scans are compared only when both retained the same effective evidence level. Mismatched or missing levels do not imply resolved or improved evidence.

Sanitised CSV

Retained evidence and SBS traceability use shared formula-injection-safe CSV sanitisation.

Supporting native evidence

Health Check, Package Licence Capacity and other native evidence remain supporting rows rather than headline scores.

Truthful availability

Unavailable or blocked evidence carries a reason, limitation and safe verification action instead of a bare Unknown or Error badge.
