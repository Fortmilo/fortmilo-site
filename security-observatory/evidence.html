Evidence & Coverage

Outcome, coverage and limitation remain separate.

Security Observatory uses the actual application vocabulary and does not assert that a Security Benchmark for Salesforce control is satisfied.

Evidence model

  • Check outcomeWhat the scanner observed or could not determine.
  • Coverage typeHow far the evidence can assess the control.
  • Retained SBS outcomePoint-in-time outcome stored with the scan.
  • Supporting toolsLike-for-like comparison and sanitised export.

Actual application terminology

Application evidence terminology

Severity

  • Critical
  • High
  • Moderate

Check outcome

  • Risk evidence
  • No risk evidence surfaced
  • Unknown/Error
  • Not applicable, where supported

Coverage type

  • Automated
  • Partial Evidence
  • Manual Required
  • Not Covered
  • Extended Check

Retained SBS outcome

  • Risk evidence
  • No risk evidence surfaced
  • Unknown/Error
  • Not assessed

SBS reference

Control identifiers and short registry fields are referenced where applicable; guidance is reached by link.

Operator judgement

Control satisfaction belongs to the user, auditor or customer governance process.

Like-for-like comparison

Completed scans compare only when both retained the same effective evidence level.

Sanitised CSV

Retained evidence and SBS traceability use formula-injection-safe sanitisation.

Visible limitations

Unknown, error, unavailable and not-assessed evidence remains explicit rather than disappearing.
