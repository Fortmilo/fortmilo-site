Evidence & Coverage

Evidence state, coverage and limitation remain separate.

Security Observatory uses evidence-bounded terminology and does not assert that a Security Benchmark for Salesforce (SBS) control is satisfied. The product implementation source supporting source-established statements is privately maintained; those statements remain self-attested unless a public artefact is cited. Exact-candidate and environment-specific validation is stated separately rather than implied.

Evidence model

  • Execution outcomeWhether the scanner or orchestration step reached a known state.
  • Source availabilityWhether the required source was accessible and sufficiently complete.
  • Rendered evidence stateThe customer-facing state justified by execution, availability and retained evidence.
  • CoverageHow far available evidence can assess the mapped question.
  • Supporting toolsLike-for-like comparison and explicit user-initiated sanitised export.

Release-status boundary

Current claims are evidence-classed, not universally release-validated

Selected genuine-zero, unavailable-source and classified scanner-failure paths have automated-test and controlled runtime evidence in a reviewed Salesforce environment. Running-user sharing, CRUD and field-level-security behaviour, complete raw-IP data-shape handling and environment compatibility remain separate exact-candidate or environment-specific validation questions. Public package installation is not yet claimed.

Evidence terminology

One canonical rendered vocabulary

The rendered state is selected according to the limiting evidence dimension. Partial is a completeness qualifier, not a separate state. Coverage remains a separate axis for SBS and other supporting-framework review. A retained state is the point-in-time rendered state stored with a scan.

Read this before drawing conclusions

What a result does not mean

  • Not a compliance decision. An SBS control reference is a version-bound pointer to retained evidence, not a statement that the control is satisfied, compliant or secure.
  • None found is not a pass. It means no matching records were observed in the successfully assessed scope — not that the control passed or that exposure cannot exist outside the assessed sources.
  • Unavailable is not zero. When a required source cannot be assessed, the result remains non-positive and carries a bounded reason and safe next action. Selected current paths have test and controlled runtime evidence; universal environment support is not implied.
  • History is not rewritten. A later SBS registry or mapping change does not alter what an already-completed scan means; each scan keeps the registry version and mapping revision it ran with.
  • Counts are family-scoped. A retained family finding count belongs to the mapped scanner family, not uniquely to one SBS control.

SBS overlay

An independent benchmark, used as an optional layer

Security Observatory can attach Security Benchmark for Salesforce (SBS) control references to a scan. SBS is maintained by its own editorial board and contributors and published under CC BY-SA 4.0. It is not owned, published, endorsed or supported by Salesforce, and it is not a FortMilo benchmark.

Optional, not required

Security Observatory works without SBS enabled. Turning it on adds a reference layer on top of the same underlying evidence — it does not change what is scanned.

Version-stamped per scan

A scan run with SBS enabled is stamped with the SBS registry version and mapping revision used for that run, so a later catalogue change does not silently rewrite what an older scan meant.

Bounded, not reproduced

FortMilo stores only bounded registry fields — control ID, short title, domain, category and local mapping fields — never SBS audit procedures, remediation guidance or control prose.

Not a compliance decision: Security Observatory does not determine whether an SBS control is satisfied.

Retained traceability

Control, family, state and outcome stay linked — not merged

SBS traceability is not a control ID stamped directly onto every finding. It is a retained, version-bound relationship: retained SBS control → retained mapped scanner family or families → retained scanner-family evidence state → retained control outcome → related retained family findings. Every part of that chain comes from the selected scan's own retained records, so a later catalogue change cannot reinterpret an older scan.

What a traceability row shows

  • Control key, title, domain and category
  • Coverage type and mapped scanner families
  • Retained family evidence state
  • Retained control outcome
  • Retained family finding count
  • Degraded-source flag and sanitised cause
  • Limitation and safe next action

What mapping metadata is not

  • No numeric or High/Medium/Low confidence score
  • Coverage type describes evidence depth, not confidence
  • Family rank orders multiple families — it is not a score

Mapping metadata fields

  • Coverage type
  • Scanner-family key
  • Family rank (ordering)
  • Optional limitation code
  • Mapping revision

Findings are joined, not stamped: a finding carries its own identity and scanner-family relationship; the SBS control separately retains the mapped scanner-family reference. Traceability joins the two through the shared scanner-family key. It is accurate to say retained findings can be related to retained SBS controls through that relationship — not that every finding carries an SBS control ID.

Export controls

Each surface exports a fixed allow-list

There is no single universal retained-evidence CSV schema — each evidence surface exports the fixed allow-list of display fields appropriate to it. The current SBS control-traceability export uses its own fixed set of columns, and the shared JavaScript export helper applies the current sanitisation controls to the enumerated helper-backed export paths.

SBS control traceability export — 14 columns

Scan Number, Retained Registry Key, Retained SBS Version, Retained Mapping Revision, Control Key, Control Title, Domain, Coverage Type, Mapped Scanner Families, Retained Family Evidence State, Retained Control Outcome, Retained family findings, Degraded Source, Sanitised Cause.

Spreadsheet formula-trigger mitigation

In the reviewed JavaScript export helper, every header and cell is quoted, embedded quotes are doubled, and tabs, carriage returns and line feeds are flattened to spaces. If a cell begins with =, +, - or @, an apostrophe is prefixed. This applies to the reviewed export helper paths and the enumerated trigger characters. It is not a claim that every spreadsheet-injection technique or every export path is covered.

Sensitive-value boundary

The reviewed helper-backed export paths exclude raw Salesforce IDs, raw queries, stack traces, tokens, session identifiers, credentials and certificate bodies. Raw-IP omission or redaction is a design boundary whose complete retained-data and export-shape validation remains environment-specific.

Like-for-like comparison

Compared only when the comparison is fair

The default comparison path uses the two latest completed scans for the same source Salesforce organisation. A manually selected comparison is restricted the same way, and cross-organisation comparison is rejected. Legacy scans made before the newer source-organisation lookup existed can be compared only when both carry the same retained legacy organisation ID.

Same evidence depth required

Every scan persists the evidence depth used for that run — TopIssues, Balanced or Everything. The same scanner plan runs at every depth; the level controls how much safe detail is retained, displayed, compared and exported. Comparison is available only when both scans share the same supported evidence depth, so omitted detail is never mistaken for improvement.

What gets compared

Numeric metric deltas; findings classified as New, Resolved, Repeated, Worsened or Improved; asset snapshots classified as New, Removed or Changed; and incomplete-evidence or scanner-error context carried by both scans.

Not an SBS drift engine

This is a general retained-scan comparison, not a control-by-control SBS version-drift engine. It does not track how an individual SBS control's mapping changed between registry versions.
