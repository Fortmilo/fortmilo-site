SBS & Evidence session

Availability, coverage and result are separate.

The Observatory keeps scanner availability distinct from benchmark coverage and latest result so missing or incomplete evidence cannot be mistaken for a pass.

Three evidence axes

  • Scanner availabilityDid the scanner return usable evidence?
  • SBS coverageHow far can the Observatory evidence the control?
  • Latest resultWhat did the latest completed evidence show?

Axis one

Scanner availability

This axis describes whether the scanner family returned usable evidence. It is not an SBS result.

Evidence returned

The scanner family returned usable evidence at the configured level.

Zero observed

The scanner completed and explicitly observed zero matching records.

Not assessed — reason

The source was unavailable, blocked or incomplete. The UI states the unavailable evidence and the next safe action.

“Scanner issue” is expressed as a reason for Not assessed rather than a separate result vocabulary.

Axis two

SBS coverage status

  • AutomatedThe Observatory directly checks the control.
  • Partial EvidenceUseful evidence exists but cannot fully prove the control. This is not partial compliance.
  • Manual RequiredGovernance, process or external evidence is required.
  • Not CoveredThe current implementation does not cover the control, or the installed registry cannot resolve the mapping.
  • Extended CheckAn Observatory security check has no direct SBS control mapping.

Axis three

Latest result

  • Not EvaluatedNo completed scan has evaluated the mapped evidence, or the coverage state does not permit an evaluated result.
  • PassThe latest completed scan found no finding for the mapped evidence. This is not certification.
  • FailThe latest completed scan found one or more findings.
  • Unknown/ErrorThe scanner failed or evidence is incomplete. It never counts as Pass.
  • Manual RequiredThe control cannot be proven by scan alone.
