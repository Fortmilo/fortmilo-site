Salesforce Security Observatory

A security cockpit, not an evidence dump.

The Observatory organises read-only Salesforce security evidence by operator intent: establish whether the scan is trustworthy, prioritise findings, inspect supporting evidence and manage safe scan controls.

Explore Findings Public application repository

What it is

An in-org evidence layer

The Observatory combines a Lightning Web Components dashboard, Apex orchestration, scanner classes, Salesforce platform reads and sanitised evidence objects.

Its purpose is to make security review easier to explain and repeat. It does not remediate the organisation, verify credentials by attempting to use them or move evidence to a FortMilo-hosted service.

What the current implementation adds

Evidence that remains bounded by what Salesforce exposes

The product is deliberately positioned around evidence quality and safe review rather than a broad security score.

OAuth-first review

OAuth grants requiring review

Retained authorisation records are associated with users and applications without being described as live or usable credentials.

Application evidence

Connected App Evidence Passport

Application identity, authorisation context, safe user associations, governance context and source limitations are brought into one bounded view.

Coverage honesty

Explicit non-assessed states

Blocked, unavailable or unretained evidence is not converted into zero, clean, passed or low-risk output.

Supporting framework

SBS control-identifier mapping

Validated evidence can be mapped to Security Benchmark for Salesforce control identifiers without asserting compliance or producing a pass/fail result.

Operational evidence

Comparison and safe export

Like-for-like retained scans can be compared at the same evidence level, and CSV output uses formula-injection-safe sanitisation.

Trust boundary

No data egress

Scanning and evidence storage remain inside the subscriber Salesforce organisation.

How it works

One complete scanner plan

  1. An authorised operator starts a manual scan or an enabled admin-managed schedule invokes the same scan path.
  2. Apex orchestration runs the configured scanner plan and records sanitised status, metrics, findings and safe detail.
  3. The selected evidence level controls retained and displayed depth; it does not select a different scanner list.
  4. Operators review findings, supporting evidence, limitations, comparison and safe exports in Salesforce.
