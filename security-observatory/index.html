Governed application lifecycle

Move from observed evidence to accountable review context

Security Observatory maintains durable governed application records from the evidence sources supported in V1. Records can hold ownership, vendor, purpose and review context, while retaining links to source provenance, OAuth usage and associated findings.

  1. ObserveCollect supported, bounded evidence.
  2. Create or reconcileLink observed evidence to a durable governed asset conservatively.
  3. Add contextRecord ownership, vendor, purpose and review details when known.
  4. Retain provenanceKeep the source and evidence boundary visible.

Scope boundary

V1 limitations

V1 scope current as of 3 September 2026.

  • Free V1 is single-org.
  • It is read-only and advisory, performs no automatic remediation, and does not revoke tokens, remove permissions or alter assessed endpoints or Salesforce security configuration.
  • Historical evidence is bounded to 1–10 retained completed scans. Current defaults are Developer Edition 1, Sandbox 3 and Production 3.
  • OAuth usage rows follow scan-retention cleanup even when governed application and source records are longer-lived.
  • Licence assignment evidence is bounded to 1,000 retained records per family across Package Licences, Permission Set Licences and Salesforce User Licences. Safe capture can be lower because Salesforce transaction and DML headroom must be preserved.
  • Package Licence capacity evidence is available for managed packages that expose a Salesforce PackageLicense record. This is not a complete installed-package inventory.
  • The asset and governance CSV does not export the complete governance record.
  • External Client App inventory is not included in V1.
  • Some Tooling API evidence requires the subscriber to complete self-callout setup.
  • SBS mapping is not promoted as release-complete while the current application requirement remains partial and open.
  • Unavailable or incomplete evidence is not presented as zero.

Future direction

Paid extensions for continuous monitoring, longer evidence history and estate-wide governance are under consideration for a later release.

Evidence boundary

Conclusions stay tied to what was observed

Missing evidence must never become a clean result. Source provenance, observed-zero, unavailable, incomplete and not-retained states remain distinct so a review does not overstate what the scan established.

Collection and retention occur inside the subscriber Salesforce organisation. The authenticated browser prepares allow-listed CSV content; downloading creates a separate file boundary outside Salesforce.
