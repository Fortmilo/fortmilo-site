Architecture

Runs inside Salesforce with a narrow evidence boundary.

LWC, Apex orchestration, scanner classes, safe platform reads and sanitised in-org evidence.

Architecture boundaries

  • Salesforce-nativeLWC dashboard, Apex services and Salesforce data storage.
  • Read-only scanningSOQL, Tooling API and safe metadata reads.
  • Subscriber-owned authenticationManual self-callout configuration remains controlled by the installing organisation.
  • Truthful degradationMissing Tooling access becomes Not assessed, never a false zero.

Execution path

One Apex-owned scanner plan

LWC dashboard→SecurityObservatoryController→SecurityScanService→Scanner classes→Safe Salesforce reads

Security boundaries

Deliberately read-only

No remediation

No token revocation, API blocking, permission removal, endpoint change or production security write-back.

No raw credentials

No tokens, session IDs, client secrets, certificate bodies, private keys, raw headers or raw IP values.

No external evidence service

Scanning and retained evidence remain in the subscriber Salesforce organisation.

Self-callout prerequisite

Manual subscriber-owned authentication

Tooling-backed scanner families require subscriber-specific Auth Provider, External Client App, External Credential, Named Credential and principal configuration.

External Client App inventory is not claimed.
These references describe the subscriber-owned self-callout prerequisite and principal context only.
