Findings

Triage first. Detail on demand.

The Findings session groups retained evidence for operator review, supports filtering and opens bounded detail without rendering every retained row in the main flow.

Finding workflow

What an operator can do

Implemented

Filter and prioritise

Focus retained findings by severity, finding area, review state and supporting SBS or Extended Check context.

Implemented

Open safe detail

Review evidence summary, source, limitation, verification route and bounded supporting rows in a detail surface.

Implemented

Record advisory review

Review status supports operational follow-up without changing Salesforce permissions, sessions, applications or endpoints.

Finding evidence states

What evidence applies to this finding?

These labels describe finding or detail evidence. They are not scanner-family status labels and they are not SBS coverage states.

  • None foundThe relevant check completed and no matching evidence was observed.
  • Not assessedThe evidence could not be assessed for the stated reason.
  • Not assessed at this evidence levelThe configured evidence depth did not assess or retain the detail required for this view.
  • Not capturedThe source did not capture the evidence required to support the finding detail.
  • UnavailableThe source or query could not be accessed reliably at the time of assessment.
  • Not applicableThe evidence question does not apply in the stated context.

Implementation boundary

Only two public implementation states

Public capability wording uses a binary state. Nuance belongs in the supporting explanation, not in a vague “partial” badge.

Implemented

Evidence-led finding review

Findings can carry source, limitation, verification help, review status and safe retained detail where the scan produced usable evidence.

Not implemented

Automatic security changes

The Findings session does not revoke tokens, remove permissions, block APIs, change endpoints or attempt remediation.

Not implemented

Credential replay or token testing

The Observatory does not test whether a retained authorisation works by attempting to use the credential.

Domain catalogue intentionally withheld. A public domain-by-domain implementation catalogue will be published only after current scanner validation supports a truthful binary status for every listed domain.

Evidence boundary

Missing evidence never becomes a clean result

A blocked source, unavailable query or unassessed detail remains visible as a bounded non-clean state with a reason and a safe next action.

A retained OAuth authorisation record is not described as a live or usable token unless separate retained platform evidence proves that narrower statement.
