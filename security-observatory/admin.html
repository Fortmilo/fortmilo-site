Admin session

Safe controls around one complete scan plan.

The Admin session controls evidence depth, completed-scan retention, scheduled execution, stale-lock recovery and the local SBS registry.

Admin boundaries

  • Permission gatedSettings and recovery require explicit Observatory administration access.
  • Disabled by defaultScheduled scans use fixed Weekly or Monthly presets.
  • No free-form CRONThe first scheduling slice avoids arbitrary scheduling input.
  • No remediationControls manage Observatory execution and evidence only.

Evidence levels

Depth, not scanner selection

Manual and scheduled scans use the same Apex-owned scanner plan. The evidence level changes what is retained, displayed, compared and exported.

Top IssuesRetains and displays the highest-value evidence.
BalancedAdds safe drill-down evidence to the top-issue view.
EverythingRetains full-detail evidence and therefore uses the most storage.

Scan operations

Manual and scheduled execution share the same path

One Scan action

Client code does not own a second scanner list. The same complete scanner plan runs regardless of trigger.

Scheduled scans

Admin-managed, disabled by default and restricted to Weekly or Monthly presets. Overlapping scans are prevented.

Operational status

The Admin area shows enabled state, frequency, next run, last run and last outcome using sanitised status only.

Retention

Bounded completed-scan history

Administrators select a completed-scan maximum from 1 to 10. Defaults are Developer Edition 1, Sandbox 3 and Production 3. Developer Edition Everything evidence is capped at one completed scan.

When the cap is reached, the oldest completed evidence tree is deleted before a replacement starts. Cleanup failure prevents the new scan from starting, and replacement failure is reported honestly.

Recovery and registry

Operational recovery without Salesforce remediation

Stale scan-lock recovery

Admins may close a confirmed orphan Queued or Running scan to a bounded Failed state when no active scan-lifecycle job remains.

No active-job cancellation

Recent, active or ambiguous locks remain blocked. Raw scan and AsyncApexJob identifiers are not exposed.

SBS registry controls

Bundled local SBS metadata can be updated through controlled admin upload without internet update checks or automatic remapping.

Permission boundary

Admin-only and still read-only

Configuration and recovery controls manage Observatory execution and evidence storage only. They do not revoke tokens, remove permissions, block APIs, change endpoints or alter Salesforce security settings.
