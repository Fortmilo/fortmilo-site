FortMilo Lab

Salesforce architecture with a security-first boundary

FortMilo Lab is an independent software and security engineering practice founded by Salesforce architect Luca Pacini.

Its work focuses on Salesforce platform security, identity, permissions, OAuth governance, integrations, evidence quality and secure delivery patterns.

Salesforce Security Observatory

A Salesforce-native evidence layer for security review

The Observatory combines an LWC dashboard, Apex orchestration, scanner classes, safe SOQL and Tooling API reads, and in-org storage of sanitised evidence.

Connected App Evidence Passport

Per-application review of observed Connected App shells, retained OAuth grants requiring review, safe user associations, governance context and explicit source limitations.

Evidence and coverage

Every source explains what was assessed, what was unavailable and the safe next verification step. Unknown or failed checks are never presented as a pass.

Retained review

Bounded in-org scan retention, findings, safe drill-downs, source details, formula-injection-safe CSV export and like-for-like comparison where evidence levels match.

Current evidence areas

What the current implementation reviews

Coverage depends on Salesforce edition, permissions, metadata availability and completion of the documented self-callout prerequisite.

Identity and login posture

Active, frozen, administrative, inactive and stale-login users; current sessions; failed logins; delegated administration; login access and identity-policy evidence where available.

OAuth and application exposure

Connected Apps, retained OAuth authorisations, inactive or frozen-user associations and safe application-level evidence without testing credentials.

API and privilege exposure

API Enabled access, high-risk permission evidence, assigned-user context and Data Exposure Permissions such as broad data access and export-style risk.

Credentials and endpoints

Named Credentials, External Credentials, certificate inventory and expiry, outbound endpoint governance and principal context where safe evidence is available.

Sites and external surfaces

Baseline Salesforce Site and Experience exposure evidence, external endpoints and public-facing configuration signals. Deep guest-user exposure is not claimed.

Licence capacity

Package Licence Capacity, Permission Set Licence and Salesforce User Licence visibility, including totals, use and remaining capacity where the platform exposes it.

Administrative change evidence

Setup Audit Trail evidence for sensitive administrative changes, with sanitised findings and links back to the appropriate Salesforce verification path.

Supporting Salesforce evidence

Health Check and other native security evidence remain supporting sources rather than headline scores. The Observatory complements Salesforce-native products instead of cloning them.

Security Benchmark for Salesforce

SBS-aligned evidence without a compliance claim

Scanner output is mapped to local, version-bound Security Benchmark for Salesforce metadata where implementation is validated.

  • Automated — the Observatory can collect the approved evidence directly.
  • Partial Evidence — useful evidence exists, but it does not fully verify the control.
  • Manual Required — the control requires human verification.
  • Not Covered — the current implementation does not assess it.
  • Extended Check — useful Observatory evidence exists outside direct SBS control coverage.

SBS alignment is evidence support, not certification, formal compliance scoring or a pass/fail audit result.

Product position

Designed to complement Salesforce security products

Security Center Essentials is Salesforce's native starting point for key security metrics. The Observatory adds a different evidence workflow: OAuth-focused review, retained explainable evidence, explicit coverage states, safe drill-downs, comparison and sanitised export.

It does not replace Security Center Essentials, Security Center, Shield, Event Monitoring, Transaction Security, specialist security products or professional review.

Architecture

Runs inside Salesforce

LWC dashboard → Apex controller and scan service → Scanner classes → SOQL, Tooling API and safe metadata reads → Sanitised in-org evidence

Security boundaries

Read-only first, with explicit limits

No automated remediation

No token revocation, API blocking, permission removal, endpoint changes, certificate rotation or production write-back.

No attacker-useful evidence

No access tokens, refresh tokens, session IDs, client secrets, certificate bodies, private keys, raw IP values or raw sensitive headers.

Safe degradation

Tooling-backed scanners use a Named Credential self-callout. Missing or insufficient setup produces a clear “Not assessed” state rather than a false clean result.

Release status

Active development and private validation

The private implementation is being hardened for a curated public release. The public repository is a sanitised documentation, validation and contribution surface; it is not a mirror of the private repository or its Git history.

A generally available package and AppExchange listing are not yet claimed. Installation should remain sandbox-first until release readiness and clean-org proof are complete.
