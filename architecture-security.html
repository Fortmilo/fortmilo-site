Architecture & Security

Salesforce-native, bounded and explainable.

Security Observatory separates experience, orchestration, collection, evidence and governance so each documented trust boundary stays visible.

Architecture principles

  • In-org runtimeScanning, evidence and review stay inside Salesforce.
  • Read-only firstNo security remediation or production write-back.
  • Least privilegeSubscriber-owned authentication and permission-gated controls.
  • Truthful limitationsUnavailable evidence remains visible and explained.

Diagram 1

Runtime architecture

Invocation and retained-evidence paths inside the Salesforce trust boundary

Diagram key: Solid arrows show execution or evidence/result relationships, as labelled. Dashed outlines show trust or ownership boundaries.

What happensThe review surface invokes Apex orchestration and scanner families; scanner results return through sanitisation and normalisation into retained review evidence.
Security propertyCollection, retention, review and CSV generation occur inside the subscriber Salesforce organisation.
Deliberate boundaryCSV export is initiated by the user. Once downloaded, the sanitised file is outside the Salesforce trust boundary.

Diagram 2

Subscriber authentication and trust boundary

Subscriber-owned OAuth configuration for the Tooling API self-callout

What happensCore SOQL-backed evidence does not require the Tooling setup; the Tooling-backed path uses the subscriber-authenticated Named Credential self-callout.
Security propertyThe subscriber owns the OAuth registration, provider configuration, credential principal and callout endpoint; no credential values are retained as review evidence.
Deliberate boundaryIf Tooling authentication is missing, blocked or insufficient, Tooling-backed evidence is not assessed and retains a bounded reason, limitation and safe next action.

Diagram 3

Evidence lifecycle and sanitisation

Sensitive values are removed before retained review evidence

What happensScanner output is filtered, normalised and retained with provenance and limitation context.
Security propertyReview evidence excludes tokens, session identifiers, raw secrets and certificate bodies.
Deliberate boundarySanitisation limits retained review data; it does not claim that every source value is harmless.

Diagram 4

Usable evidence and unavailable evidence

Evidence availability is decided before an outcome is retained

What happensEach source or check attempt first determines whether usable evidence can be obtained.
Security propertyUsable evidence retains a bounded observed outcome; unavailable or incomplete evidence retains a non-positive state, an explicit reason and a safe next action.
Deliberate boundaryAbsence of evidence is never treated as evidence of absence.
