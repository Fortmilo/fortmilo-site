Architecture & Security

Salesforce-native. Evidence stays in the organisation.

Security Observatory separates runtime logic, subscriber authentication, evidence sanitisation and failure handling so each boundary can be reviewed independently.

Architecture principles

  • In-org runtimeScanning, evidence and review remain inside Salesforce.
  • Read-only firstNo security remediation or production write-back.
  • Subscriber-owned trustAuthentication configuration remains under the installing organisation’s control.
  • Truthful unavailabilityMissing evidence is shown as Not assessed — reason.

Four architecture views

Security boundaries shown, not hidden

Each static diagram explains what happens, the security property created by the design and the deliberate boundary that remains.

01 · Runtime architecture

One controlled evidence path

The user interface does not query sources directly. Apex owns orchestration, scanner families own bounded collection and retained evidence supports every downstream review surface.

What happens

LWC requests a bounded operation; Apex orchestrates scanner families and stores normalised evidence.

Security property

CRUD/FLS, sharing, least privilege and storage limits apply before evidence reaches user-facing surfaces.

Deliberate boundary

The architecture observes and explains posture. It does not remediate Salesforce configuration.

02 · Subscriber authentication boundary

Package the core; leave trust with the subscriber

SOQL-backed evidence uses normal Apex access. Tooling-backed evidence crosses a named-credential boundary configured after installation.

What happens

The core invokes a Named Credential; the subscriber’s External Credential, principal, External Client App and Auth Provider complete the trust chain.

Security property

No consumer secret, token or principal authentication value is embedded in the packaged application.

Deliberate boundary

Subscriber-specific OAuth setup and principal authentication remain outside the core package.

03 · Evidence lifecycle and sanitisation

Reduce before retention

The useful product is the explainable evidence model, not a copy of sensitive source records.

What happens

Source observations move through an allowlist, normalisation and evidence classification before retention.

Security property

Tokens, sessions, client secrets, certificate bodies and raw IP values are excluded from retained evidence.

Deliberate boundary

Evidence supports review, comparison and export; it is not sufficient to replay authentication.

04 · Unavailability handling

Unavailable is a first-class result

The application distinguishes usable evidence, an explicit zero observation and a source that could not be assessed.

What happens

Preflight and collection determine whether evidence is usable, explicitly zero or unavailable with a reason.

Security property

Unknown/Error and Not assessed states remain visible instead of being converted into favourable output.

Deliberate boundary

The Observatory reports the limit of its evidence; it does not claim certainty beyond what Salesforce returned.
