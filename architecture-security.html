Architecture & Security

Runs inside Salesforce with a narrow evidence boundary.

FortMilo Security Observatory uses LWC, Apex orchestration, scanner classes, safe platform reads and sanitised in-org evidence.

Architecture boundaries

  • Salesforce-nativeLWC dashboard, Apex services and Salesforce data storage.
  • Read-only scanningSOQL, Tooling API and safe metadata reads.
  • Subscriber-owned authenticationManual self-callout configuration remains controlled by the installing organisation.
  • Truthful degradationMissing Tooling access becomes Not assessed, never a false zero.

Security boundaries

What the application deliberately does not do

No remediation

No token revocation, API blocking, permission removal, endpoint change, certificate rotation or production security write-back.

No secrets or raw credentials

No access tokens, refresh tokens, session IDs, client secrets, certificate bodies, private keys, raw headers or raw IP values.

No external evidence service

Scanning and retained evidence remain inside the subscriber Salesforce organisation.

Self-callout prerequisite

Manual subscriber-owned authentication

Core SOQL-backed evidence works without the Tooling API self-callout. Tooling-backed scanner families require subscriber-specific Auth Provider, External Client App, External Credential, Named Credential and principal setup.

The package does not own or overwrite subscriber OAuth configuration.
