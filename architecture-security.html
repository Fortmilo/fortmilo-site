Architecture & Security

Salesforce-native. Evidence stays in the organisation.

FortMilo Security Observatory combines LWC, Apex orchestration, bounded scanners, Tooling API self-callouts and sanitised evidence. It is read-only, advisory and designed to fail visibly rather than report a false clean state.

Architecture principles

  • In-org runtimeScanning, evidence and review stay inside Salesforce.
  • Read-only firstNo security remediation or production write-back.
  • Least privilegeSubscriber-owned authentication and permission-gated controls.
  • Truthful failureUnavailable evidence becomes Not assessed, never zero risk.

Subscriber authentication boundary

Core evidence works without surrendering OAuth ownership

Subscriber-specific authentication remains outside the packaged core and under the installing organisation’s control.

Core path

SOQL-backed evidence

Runs through normal Apex data access and the assigned Observatory permissions. No self-callout is required.

Tooling path

Subscriber-owned self-callout

Tooling-backed scanners use an Auth Provider, External Client App, External Credential, Named Credential and named principal configured by the subscriber.

Failure path

Fail closed and explain why

Missing, unauthorised or insufficient setup produces Not assessed with a safe next action. It never produces a fabricated zero or pass.

AI-assisted engineering

AI supports development and review — not the customer runtime

The current product has no runtime AI integration. GPT/Codex and Claude are used as controlled engineering assistants around the repository, with deterministic validation and human approval remaining authoritative.

GPT

OpenAI GPT / Codex

Used for controlled source changes, refactoring, test generation, documentation and implementation planning on isolated branches or worktrees.

C

Claude

Used as an independent challenger for architecture, security boundaries, evidence wording and regression-risk review.

CI

Deterministic assurance

Apex tests, Jest, ESLint, Prettier, sensitive-data scans and package-boundary checks decide whether a change is acceptable.

H

Human release control

Deployment, commit, push, package and release decisions remain manual and explicitly approved. AI output is never treated as deployment evidence.

Runtime boundary: GPT, Claude and other models do not query subscriber Salesforce organisations, receive retained scan evidence at runtime or perform remediation.

Future advisory extension

Model-agnostic, sanitised and explicitly outside v1

A future advisory service could send an approved model endpoint — GPT, Claude or another enterprise model — a sanitised summary rather than raw Salesforce evidence.

Sanitised summary→Approved model endpoint→Strict structured response→Advisory display only
  • No tokens, sessions, secrets, certificate bodies or raw IP values.
  • No direct Salesforce query access.
  • No remediation, permission changes or production write-back.
  • Not implemented or claimed as part of the current v1 product.

Non-negotiable controls

Security boundaries are part of the architecture

No remediationNo token revocation, API blocking, permission removal, endpoint changes or security-setting write-back.
No raw secretsNo access tokens, refresh tokens, session IDs, client secrets, private keys or certificate bodies.
No false cleanUnknown, error and unavailable evidence remain visible and never count as pass.
Bounded storageRetention and comparison use explicit caps and like-for-like evidence levels.
Safe exportsCSV output uses shared formula-injection-safe sanitisation.
Evidence provenanceSource, limitation, verification path and coverage state remain visible to the operator.
